### 2-2. 큐 B 완료 — **O-7 Closed(원인 확정 불가, 재조사 불필요)** (`b966d32`·`8e60b59`·`6b3d431`)

진단 SQL 2종을 작성하고(실행은 팀장) 코드를 읽기 전용으로 판독했다.

**DB 실측(SQL Editor, RLS 우회)**

| 항목 | 값 |
|---|---|
| `reading_sessions` | **140행** |
| 완독 행 | **86행** |
| `children` | **10명** |
| 부모(`parent_id` distinct) | **10명** |
| 총량 | 완독 86 × 50 = **4,300** = 실제 포인트 합계(**보존**) |

**종결 근거 5항**

1. **부모:자녀 = 1:1**(한 부모 아래 자녀 2명 이상 0건) → `getActiveChild`
   (`lib/home/active-child.ts:51-57`, `created_at ASC LIMIT 1`)에 **선택 여지가 없다**.
   비결정적 선택·오선택이 **구조적으로 불가능**하다.
2. 두 자녀의 `parent_id`가 **다르다**(Q10 `same_parent=false`) — 키키주니어 부모
   `9f59a9ac…` / 쵸은우 부모 `d98b4767…`. **RLS 경계상 앱 완독 경로로 포인트가 계정을
   넘을 수 없다.**
3. 따라서 **"+50이 −50으로 이동"이라는 해석은 기각.** 합계 0은 **우연**이며 **무관한 두 사건**이다.
4. 현재 코드는 `child_id` **단일 출처**(`d2237d3`, 2026-07-01). 그전의 **2회 독립 해소**
   구조(`completeReadingSession`과 `awardCompletionRewards`가 각각 `getActiveChild` 호출)는
   **이미 소멸**했다.
5. 영향 범위는 **개발용 계정 2개 한정 · 실사용자 0명**.

**미해결로 남긴 것**
- ±50이 **언제·무엇으로** 생겼는지는 특정하지 못했다. 팀장도 `children.points` 수동 변경
  여부가 기억나지 않는다고 확인 — **확인 불가**.
- ★ **포인트 값은 보정하지 않고 유지한다**(키키주니어 **+50** / 쵸은우 **−50**).
  실사용자 영향이 없고, **그 차이가 유일하게 남은 흔적**이기 때문이다.

**산출물**: `scripts/sql/o7_child_id_diag.sql`(Q1~Q6) · `scripts/sql/o7_parent_scope.sql`(Q7~Q11)
— 둘 다 조회 전용, `BEGIN … ROLLBACK`, pglast 검증 통과, 보정 SQL 0건.

### 2-3. 큐 C 완료 — **O-8 Closed(정책 결정 완료, 데이터 변경 없음)** (`b5e0057`)

비활성 도서(`is_active=false`) 완독분 포인트 잔존은 **버그가 아니다** — 아이가 실제로 읽고
받은 점수이며, 책이 내려간 사유는 대부분 **교차출처 중복 처리**(book_dash판 채택 → ASb 등
중복판 비활성)다. 삭제가 아니라 비활성이라 `reading_sessions` FK는 유지된다.

**팀장 결정(안 '가' 채택)**

1. **포인트 총점은 변경하지 않는다**(데이터 보정 없음).
2. 읽은 책 목록에 비활성 도서를 **그대로 표시한다**.
3. 다만 **다시 읽기(뷰어 진입)는 차단한다**.
4. 차단 시 아이가 이해할 수 있는 **안내 문구를 노출한다**(예: "이 책은 지금 쉬는 중이에요").

**근거**: 3~7세에게 "읽은 책이 사라지는 것"은 혼란·상실감을 준다 / 목록에서 숨기면 총점과
목록 개수가 어긋나 오히려 버그처럼 보인다 / 다시 읽기를 허용하면 중복 정리가 무의미해진다.

**구현은 큐 D에 흡수**한다(같은 화면을 두 번 열지 않기 위함). **O-8 단독 코드 작업은 없다.**

### 2-4. O-10 신설 — 완독 세션 경합으로 인한 포인트 미지급 가능성 (`6b3d431`)

O-7과 **무관한 별건**이며 관측 사건이 아니라 **구조 결함**이다(코드 판독으로 발견).

- `reading_sessions`에 **UNIQUE 제약 없음**(`lib/book/reading-session.ts:97-101`).
- 시작 가드가 애플리케이션 레벨이라 **동시 요청 시 미완료 2행 INSERT 가능**(`:134-158`).
- 완독 UPDATE가 **`LIMIT` 없이** 갱신(`:212-219`) → 2행 동시 완독 → `.maybeSingle()` 실패
  → `:221` 에러 분기 → `awardCompletionRewards` **미호출** → **완독은 남고 포인트 0**.
- 방증(정황): 진행 중 세션이 이례적으로 많다 — 부모 `d98b4767…` **28행** · `9c4f345f…` **16행**.
- 판정: 실사용자 재발 가능하나 **베타 비차단**. **큐 J**("베타 종료" 선행)로 배치.
  **베타 전 코드 변경 금지 — 등록만 한 항목이다.**

### 2-5. "2,433행" 근거 확정 (`94f7b6a`)

**근거 불명이 아니었다.** 출처가 저장소에 명시돼 있었다.

- `scripts/sql/diag/session_origin_diag.sql:5-6` — **"대상: `children.name='키키주니어'`
  … reading_sessions 2,433행 = 완독 52 + 미완독 2,381"** ← 처음부터 **자녀 1명 범위 값**이다.
- `scratchpad/SESSION_NOTE_20260815.md:35` — **"정리 실측: 키키주니어 2,433 → 56행
  (삭제 2,377). 완독 52 불변."**
- 관리자 preview 세션 증식이 원인이었고 `a4c56cc`로 재발 방지 후 **2026-08-15 정리**로 삭제됐다.
- 현재 Q11 실측(56·45·32·4·2·1 = **140**)과 정확히 맞물린다.
→ **ADR-0059의 2,433 서술은 유효**하며 RPC·청크 가드 근거도 그대로다. **본문 무수정.**

**"reading_sessions 56행 / 완독 52행" 정정**: RLS 범위 문제가 **아니라** 키키주니어 1명의
**정리 후 실측값**이다. 인수인계에 **자녀 1명 수치가 전체값처럼 옮겨진 것**이 원인이다.

### 2-6. 신설 규칙 — 수치 정본화

- **수치를 정본화할 때 측정 범위(전체 / 자녀 1명 / 부모 1명)를 반드시 함께 적는다.
  범위 없는 수치는 정본으로 인정하지 않는다.**
- **두 시점의 수치를 비교할 때는 그 사이에 정리·삭제 커밋이 있었는지 먼저 확인한다.**

   다만 그 구조도 결국 부모:자녀 1:1 실측 앞에서는 원인이 될 수 없었다 — **코드 가설보다
   데이터 실측이 상위**다.
