## Context

### 1. 문제 — 자녀가 없으면 서비스를 볼 수 없다

현재 자녀 등록은 **사실상 필수**다. 로그인 직후 자녀가 0명이면 `/onboarding`으로 보내지고,
메인 `/`나 `/library`에 직접 들어가도 다시 `/onboarding`으로 되돌려진다. 자녀 프로필을
만들기 전에는 **책 한 권도 목록에서 볼 수 없다.**

그런데 실제 이용자에는 자녀가 없는 성인이 있다 — **공부방·학원 선생님**, 그리고 도입을
검토하려고 먼저 둘러보는 학부모다. 이들에게 현행 동선은 "가짜 자녀를 만들어야 서비스를
볼 수 있다"는 뜻이고, 그렇게 만들어진 행은 `children` 통계와 `reading_sessions`를 오염시킨다.

### 2. 팀장 결정 — A안(열람 개방형)

| 안 | 내용 | 판정 |
|---|---|---|
| **A. 열람 개방형** | 자녀 없이도 **열람 가능**. 기록·포인트는 **없음**. 자녀 단위 데이터 구조 **무변경** | ✅ **채택** |
| B. 성인/선생님 프로필 유형 | `profiles`에 유형을 두고 선생님 전용 기능(학급 관리·진도 추적)을 붙임 | **Phase 3 B2B 트랙으로 이관.** 본 ADR 범위 밖 |

B안은 스키마 변경과 신규 기능군을 동반해 베타 일정과 충돌한다. A안은 **기존 자녀 단위
스키마를 그대로 두고 화면 가드만 푸는** 방식이라 베타 안에서 처리 가능하다.

## Decision

### 원칙 — 기록계 기능은 자녀 0명에게 **일괄** 숨긴다

> **완독 · 즐겨찾기 · 스트릭 · 레벨 · 추천은 "기록계 기능"이며, 자녀가 0명이면
> 화면에서 일괄 숨긴다. 화면별로 개별 판단하지 않는다.**

이 원칙을 명문화하는 이유는 **말이 화면마다 달라지는 것을 막기 위해서**다. 하나는 숨기고
하나는 눌렀더니 에러가 나면, 사용자는 무엇이 되고 무엇이 안 되는지 배울 수 없다. 지금
`/read`에서 벌어지는 일(세션은 조용히 건너뛰는데 완독만 에러)이 정확히 그 상태다.

새 기능을 추가할 때도 이 원칙이 판정 기준이다 — **"자녀 단위 데이터를 쓰는가"** 로 묻고,
그렇다면 자녀 0명 화면에서 숨긴다. 예외를 두려면 본 ADR에 Amendment를 남긴다.

### D1 — 자녀 0명 로그인 사용자의 `/`는 **전용 블록**을 렌더한다 (Q1-b)

`app/page.tsx:146-148`의 `redirect(ONBOARDING_PATH)`를 제거하고 **네 번째 갈래**를 만든다.
구성: **상단 "자녀 등록하기" 유도 카드 → 인기 책 → 카테고리**.

`MemberMain` 재사용은 불가하다 — `components/main/member-main.tsx:35-47`이 `child`·
`recommendation`·`streakDays`를 필수로 요구하고, 인사말은 `lib/home/greeting.ts:66-75`가
`child.name`을 읽는다.

`AnonymousMain` 재사용 여부는 **구현 설계에서 판단**하되, 어느 쪽이든 다음을 전제로 한다:

> **`components/main/anonymous-main.tsx`의 비로그인 하드코딩 4곳 해소**
> — `:59` `ctaHref={SIGNUP_PATH}` · `:62` · `:66` · `:74` `signedIn={false}`

해소하지 않으면 로그인한 사용자의 히어로 CTA·표지 카드·카테고리 타일이 전부 `/signup`으로
간다(`category-carousel.tsx:86`·`:88`, `book-cover-card.tsx:65`, `hero-cover-stack.tsx:88`).
**이미 로그인한 사람을 가입 페이지로 보내는 것은 명백한 오동선이다.**

> **실측 정정 (2026-08-20)**: 작업지시서 K-1은 하드코딩 위치를 `:60`·`:62`·`:66`·`:74`로
> 인용했으나, 로컬 실측 결과 `:60`은 `ctaLabel={copy.hero.ctaLabel}`이고 하드코딩은 `:59`
> `ctaHref={SIGNUP_PATH}`다. **개수 4곳은 정확**하며 라인만 정정한다.

### D2 — 로그인 도착지: 자녀 0명 + 미스킵이면 **최초 1회만** `/onboarding` (Q2-b)

`lib/auth/resolve-post-login-path.ts:25-26`이 **단일 수정점**이다. 호출부 3곳
(`app/login/actions.ts:67`·`:104`, `app/auth/callback/route.ts:38`)은 이 함수 하나만
고치면 전부 따라온다 — 호출부를 개별 수정하지 않는다.

판정: `자녀 0명 AND 스킵 기록 없음` → `/onboarding`. 그 외 전부 `/`(`POST_LOGIN_PATH`).

즉 온보딩은 **없어지지 않고 첫 만남에만 남는다.** 자녀 등록을 권하는 자리는 유지하되,
한 번 거절한 사람을 매 로그인마다 같은 화면으로 되돌리지 않는다.

### D3 — 스킵 기억은 **쿠키**. DB 스키마는 변경하지 않는다 (Q3-b)

쿠키를 쓰므로 **Hard Rule 8(스키마 변경 시 ADR 선행)은 발동하지 않는다.**
본 ADR 전체를 통틀어 마이그레이션 0건이다.

한계를 명시한다 — 쿠키는 기기·브라우저 단위이므로 **다른 기기에서 로그인하면 온보딩을
한 번 더 만난다.** 베타 규모에서는 감수 가능한 비용으로 판단한다(권유 화면이 한 번 더
뜨는 것이지 이용이 막히는 것이 아니다).

**승격 조건**: 사용자가 늘어 이 재노출이 실제 불만으로 관측되면 `profiles`에 컬럼을
추가한다. 그때는 **별도 ADR + 팀장 사전 승인**이 선행한다(Hard Rule 8).

### D4 — 완독 버튼은 자녀 0명이면 **미렌더** (Q4-a)

`app/(reader)/book/[id]/read/page.tsx`에 `getActiveChild` **1회**를 추가하고
(현재 이 파일은 호출하지 않는다), `:225` `finishSlot`·`:301` `FinishButton`을 조건부로 만든다.

이로써 `lib/book/reading-session.ts:204-208`의 생짜 에러에 도달할 경로가 사라진다.
**서버의 에러 반환 자체는 그대로 둔다** — 안전망이다(§불변 사항).

세션 시작이 조용히 건너뛰는 것(`:127-131`)과 **동작이 대칭**을 이룬다. 이것이 §원칙 절이
말하는 "말이 화면마다 달라지지 않게" 하는 실행이다.

### D5 — 즐겨찾기 하트는 **미렌더 유지** (Q5-a)

`app/(reader)/book/[id]/page.tsx:180-182`의 `{activeChild && <FavoriteButton/>}`를 그대로
둔다. **책 상세가 이미 채택한 선례를 확장**하는 것이지 새 규칙이 아니다.

"렌더하되 클릭 시 자녀 등록 유도"는 전환율에 유리할 수 있으나 문구 신설과 판단 분기를
동반한다. **베타 후 개선 후보로 `docs/backlog.md`에 기록**하고 본 ADR에서는 채택하지 않는다.

### D6 — `/library` 가드 3줄을 삭제한다 (Q6)

`app/(reader)/library/page.tsx:89-91`을 삭제한다. 그 외 변경은 없다.

근거는 실측이다 — `activeChild`가 이 파일에서 **가드 외 용도로 전혀 쓰이지 않는다**
(`:59` "activeChildId는 LibraryBrowser에 미주입", 조회는 `getBooks(supabase, filters, null)`).
따라서 **목록·필터·페이지네이션은 자녀 없이 그대로 동작해야 한다.**

이 "그대로 동작"은 가정이 아니라 **검증 대상**이므로 회귀 체크리스트에 등재한다(§회귀 4번).

### D7 — 의도 문서 3건에 "자녀 0명 정책" 절을 신설한다 (Q7-b)

현행 의도 문서는 "자녀 0명 → onboarding"을 **정본으로 박제**하고 있어, 고치지 않으면
문서와 구현이 즉시 어긋난다.

| 문서 | 개정 대상 |
|---|---|
| `docs/intent/screen-02-home.md` | `:52`·`:55`·`:73`·`:197` — 자녀 0명 가드 서술. **덤으로 `/home` 폐지(ADR-0062 D2) 미반영분도 함께 정리한다** — 이 문서는 아직 `/home`을 현역 라우트로 서술 중이다 |
| `docs/intent/screen-05-celebrate.md` | `:56`·`:113` — `/library` 3-가드 중 "자녀 0명 onboarding" 항목 |
| `docs/intent/screen-04-reader.md` | `:91` — 서술은 이미 정합하나, "정식 처리는 온보딩 가드가 담당"이라는 꼬리를 본 ADR 기준으로 갱신 |

`docs/intent/screen-03-book-detail.md:85`는 **개정 불요** — 이미 "책 상세는 자녀 무관
페이지"로 정합하다.

### D8 — 마이페이지 메뉴 노출을 유지한다 (Q8-a)

`components/app/app-header.tsx:81-87`의 마이페이지 링크를 그대로 둔다.
자녀 0명이 눌러 도착하는 안내 화면은 **ADR-0063·큐 D-5c에서 이미 구현**됐다
(`app/(reader)/mypage/page.tsx:99-133` — redirect 없이 안내 1장 + 온보딩 CTA).

숨기는 쪽으로 뒤집으면 그 구현이 사장되고, 자녀 등록을 권하는 자리도 하나 줄어든다.

## Non-goals (범위 외)

1. **DB 스키마 변경 일체.** 마이그레이션 0건이 본 ADR의 합격 조건이다.
2. **선생님 전용 기능** — 학급 관리, 다수 학생 진도 추적, 반 단위 리포트.
   **B안 = Phase 3 B2B 트랙.**
3. **`AnonymousMain` 이외의 공유 컴포넌트 개조.** `StreakChart`·`LevelSelector`·
   `LibraryBookCard`·`SectionHeader` 등은 손대지 않는다. 자녀 0명 화면에서 **렌더하지 않을 뿐**
   컴포넌트 자체는 무변경이다.
4. **다자녀 선택 UI.** `getActiveChild`의 "created_at ASC LIMIT 1" 계약은 그대로다.
5. **비로그인 사용자의 열람 허용.** 본 ADR은 **로그인했으나 자녀가 없는** 사용자만 다룬다.
   `PROTECTED_PREFIXES`는 변경하지 않는다.

## 이 ADR 구현 시 침범 금지 항목 (회귀 체크리스트 5건)

1. **AttributionBox 행 비축소 + H1 인접** — CC BY 4.0 법적 의무(Hard Rule 1).
   자녀 유무와 무관하다.
2. **오디오 리더 ⓘ 팝오버 어트리뷰션** — 1탭 도달 경로 유지.
3. **표지 폴백 6표면(+MainHero)** — `AnonymousMain` 개조가 `BookCoverCard`·`HeroCoverStack`의
   `onError` 폴백을 건드리지 않을 것.
4. **`/library` 목록·필터·페이지네이션이 자녀 없이 온전할 것** (D6) — 가드 삭제 후 실제 진입 검증.
5. **자녀 ≥ 1 사용자의 기존 동선 무변화** — 메인 개인화 블록·완독·즐겨찾기·스트릭이
   현행 그대로일 것. 본 ADR은 **자녀 0명 경로만** 바꾼다.

## Alternatives

### (a) 현행 유지 (자녀 등록 필수) — **기각**

선생님 세그먼트가 서비스를 볼 방법이 없다. 가짜 자녀 행이 만들어져 `children` 통계와
`reading_sessions`를 오염시키는 부작용도 이미 관측 가능한 위험이다.

### (b) B안 — 성인/선생님 프로필 유형 신설 — **Phase 3 이관**

방향으로는 옳지만 `profiles` 스키마 변경 + 선생님 전용 기능군을 동반해 베타 일정과 충돌한다.
A안이 먼저 진입 장벽을 없애고, B안은 B2B 수요가 확인된 뒤 그 위에 얹는다.

### (c) 자녀 0명에게 `/library`만 열고 `/`는 계속 온보딩으로 — **기각**

메인이 여전히 막히면 "둘러보기"가 성립하지 않는다. 사용자는 `/library` URL을 알지 못한다.

### (d) 스킵을 기억하지 않고 매 로그인 온보딩 경유(스킵 링크만) — **미채택**

스키마·쿠키 모두 0건이라 가장 싸지만, 거절한 사람에게 같은 화면을 반복 노출한다.
D3의 쿠키는 그 반복을 없애면서도 스키마를 건드리지 않는 중간값이다.

## Consequences

### 좋아지는 것

- 자녀 없는 성인(선생님·검토 중인 학부모)이 **가짜 자녀를 만들지 않고** 서비스를 둘러본다.
- `children`·`reading_sessions`의 통계 위생이 개선된다(더미 자녀 유입 감소).
- `/read`의 완독 비대칭(§Context 3)이 해소돼 **동작이 일관**된다.
- 온보딩이 "관문"에서 "권유"로 바뀌어, 등록이 사용자의 선택이 된다.

### 나빠지거나 늘어나는 것

- `/` 분기가 3갈래 → **4갈래**로 늘어 `app/page.tsx`의 복잡도가 올라간다
  (ADR-0062 §Consequences가 이미 경고한 위험의 연장선이다).
- 자녀 0명 상태가 **정상 상태로 승격**되므로, 앞으로 자녀 단위 기능을 추가할 때마다
  "자녀 0명일 때 무엇을 보이나"를 매번 판단해야 한다 → §원칙 절이 그 판단 비용을 고정한다.
- 쿠키 기반 스킵은 기기 간 이동 시 재노출된다(D3에 한계 명시).
- 온보딩 완료율이 떨어질 수 있다. **의도된 트레이드오프**이며, 떨어진 만큼이 종전에
  강제로 만들어지던 더미 자녀일 가능성이 있다.

### 변하지 않는 것

- **DB 스키마·RLS·마이그레이션** — 0건.
- **미들웨어** — 자녀 수를 보지 않는 현행 유지(ADR-0011 결정 1).
- **비로그인 사용자** — `PROTECTED_PREFIXES` 무변경. 로그인은 여전히 필수다.
- **자녀 ≥ 1 사용자의 모든 화면** — 현행 그대로.
- **자녀 단위 데이터 모델** — `reading_sessions`·`favorites`·`child_badges`·`children.points`
  전부 `child_id`를 축으로 유지한다.

## Open Questions

본 ADR의 D1~D8은 2026-08-20 팀장 승인으로 확정됐다. 구현 단계(큐 K)에서 결정할 잔여 항목만 남긴다.

### O-K1 — 자녀 0명 전용 블록을 별도 컴포넌트로 분리할 것인가

`AnonymousMain`을 `signedIn` 파라미터화해 재사용할지, `NoChildMain`을 신설할지.
**구현 설계에서 판단**하되 D1의 하드코딩 4곳 해소는 어느 쪽이든 전제다.

### O-K2 — "자녀 등록하기" 유도 카드의 문구·형태

`lib/mypage/copy.ts` 선례처럼 단일 출처를 둘지, 랜딩 카피(`lib/landing/copy.ts`)에 합칠지.
마이페이지 안내 화면(ADR-0063)과 **어휘를 맞춰야 한다** — 같은 상태를 두 가지 말로 부르지 않는다.

### O-K3 — 스킵 쿠키의 이름·수명·SameSite

D3이 방식만 확정했다. 구체값은 구현 시 결정하고 본 절에 기록한다.

### O-K4 — 자녀 0명 사용자의 `/book/[id]` CTA 문구

`ReadButton`은 그대로 노출된다(열람은 허용). 읽고 나면 완독 버튼이 없다는 점을
사전에 알릴지, 아무 말 없이 둘지. **D4의 범위 밖**이므로 별도 판단이 필요하다.
