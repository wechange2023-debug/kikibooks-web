## 요약 (먼저 읽을 5줄)

1. **54권 전부 조회·파싱 성공. 파싱 실패 0권.** 장면 경계를 깨는 구조 이상(고아 텍스트 · `<p>` 밖 이미지 ·
   한 `<p>`에 이미지 2장)이 **54권 통틀어 0건**이다. 이 코퍼스는 규약이 놀랍도록 균일하다.
2. 분류: **CLEAN 41 / MINOR 7 / MANUAL 6 / FAIL 0**.
3. **사람 판단이 필요한 6권은 전부 이미 블랙리스트**(`BOOK_DASH_404_SOURCE_IDS` 15권 소속)다.
   즉 **사용자에게 보이는 39권 기준으로는 MANUAL 0권** — CLEAN 34 + MINOR 5뿐이다.
4. 블랙리스트 15권은 원본 이미지가 **전량 404**(181장)다. 반대로 비블랙 39권은 **469장 결손 0**.
   블랙리스트 15권은 이 54권 안에 **전원** 들어 있다 — 이미지 결손은 v1 html 코호트 고유 문제다.
5. **왜 이 54권만 html로 남았는가**: 원본 구조 차이가 아니라 **적재 순서 때문**이다. v1(GH Pages)이 먼저
   적재했고, v2(WP PDF → 이미지 시퀀스)가 같은 책을 **DUP로 건너뛰었다(49권)**. 근거는 §3.

## 3. 조사 항목 3 — 116/152권 파이프라인과의 차이 (왜 이 54권만 html인가)

원본 스킴 차이가 **아니다.** 적재 경로와 순서의 문제다.

| 코호트 | 적재 스크립트 | 원천 | content_type | 뷰어 |
|---|---|---|---|---|
| **html 54권** | `scripts/sync_book_dash.py` | GH Pages HTML(meta.yml) | `'html'` | 외부 페이지 iframe (`HtmlReader`) |
| **v2 155권**(→ book_text 152) | `scripts/sync_book_dash_v2.py` | WP 카탈로그 → PDF | `'asb_native'` | 자체 뷰어 (`AsbReader`) |

**증거 — 두 코호트는 완전히 서로소인데, 원본은 겹친다:**

```
html54 ∩ population_154 = 0권      (PDF 하베스트 모집단에 한 권도 없음)
html54 ∩ WP 카탈로그(206) = 49권    (원본 PDF는 카탈로그에 있음)
WP 카탈로그 − population_154 = 52권, 그중 49권이 정확히 html54
```

ADR-0047의 회계 `206 = DUP skip 49 + v2 적재 155 + 게이트① skip 2`에서 **DUP skip 49 = html 54권 중 49권**이다.
v1이 먼저 적재해 둔 책을 v2가 중복으로 판정해 건너뛰었고, 그래서 이 49권은 PDF 하베스트·페이지 이미지 렌더·
`book_text` 적재를 **한 번도 거치지 않았다.**

나머지 5권(`i-can-dress-myself` · `little-sock` · `maddy-moona` · `mrs-penguins-palace` · `springloaded`)은
WP 카탈로그에 같은 slug이 없다 — 2026-07-07 인수인계가 기록한 **슬러그-예외**(little-sock · maddy-moona ·
mrs-penguins-palace)에 2권을 더한 집합이다. 부재가 아니라 slug 표기 불일치일 가능성이 크나, **본 정찰에서
확인하지 않았다**(WP 카탈로그 제목 대조 미실시).

**따라서 전환 재료는 두 갈래가 있다:**
- (A) GH Pages HTML·이미지를 그대로 쓴다 → 본 정찰이 측정한 경로. 즉시 가능하나 해상도가 낮다(§4).
- (B) 비블랙 39권 중 **38권은 WP 카탈로그에 PDF가 있다**(없는 건 maddy-moona 1권뿐) → 152권과 **똑같은**
  하베스트·렌더 파이프라인을 재사용할 수 있다. 해상도·정합성이 152권과 같아진다.

## 6. 정찰 중 확인된 부수 사실

1. **`extract_text.py`의 이미지 URL 버그** — `to_abs_image_url`이 `src.lstrip('/')` 후 책 폴더에 이어붙인다.
   이 코퍼스에는 src 규약이 두 가지 섞여 있다:
   - 상대경로 `images/01.jpg` (대다수)
   - **루트절대 `/bookdash-books/{slug}/en/images/01.jpg`** — `a-fish-and-a-gift` 1권 확인
   후자에 대해 경로가 두 번 겹쳐 404가 난다(`.../a-fish-and-a-gift/en/bookdash-books/a-fish-and-a-gift/en/images/01.jpg`).
   본 정찰 스크립트는 고쳤고(§실측으로 567×567 12장 정상 판독), 당시 `extract_text.py`는 읽기 전용 원칙에 따라
   손대지 않았다.
   > **후속 (2026-07-28)**: `extract_text.py`를 `urljoin` 방식으로 수정 완료. `a-fish-and-a-gift` 12장
   > 전량 200(206) 확인. 같은 함수를 재사용하는 `scripts/copy_bookdash_images.py`도 함께 정상화된다.
   > TTS 전량 배치 산출(116권·1,464유닛·124,213자)에는 영향 없음 — 해당 경로는 GH Pages가 아니라
   > DB `book_text`를 읽는다(§검증).
2. **GH Pages 간헐 503** — `walking-together/images/09.jpg`가 1회 503 후 재요청 200. 재시도 없이 세면
   멀쩡한 이미지가 결손으로 잡힌다. 스크립트에 1회 재시도를 넣었다.

## 7. 전환 시 필요한 작업 단계 (나열만 — 구현·결정 아님)

**선행 결정 3건 (팀장 판단 사항)**
- D-1. 재료를 (A) GH Pages 이미지로 할지 (B) WP PDF 재하베스트로 할지. (B)는 38/39권 가능, 해상도 152권과 동일.
- D-2. 스프레드를 좌/우로 **분할할지 유지할지**. 분할 시 Ruth 44권 오디오의 page_index 정합이 깨진다(§5).
- D-3. 블랙리스트 15권을 이번 전환에 포함할지(=PDF 경로로 이미지 복원 시도), 계속 차단할지.

**실행 단계 (D-1을 (A)로 가정한 최소 경로)**
1. 이미지 확보 — GH Pages `images/NN.jpg` → Storage `book-images/book_dash-{source_id}/NN.jpg`
   (ADR-0036 창고 복사 방식 B 재사용). **루트절대 src 규약 처리 필수**(§6-1).
2. 텍스트 확보 — 장면별 `<p>` 텍스트 추출. 무텍스트 면은 alt 폴백 또는 빈 자막으로 확정(MINOR 7권 정책).
3. `book_text` 적재 SQL 생성 — `page_index = 장면번호 − 1`, blocks JSONB
   (`scripts/pdf_harvest/gen_book_text_sql.py` 패턴 재사용). **팀장이 SQL Editor에서 실행**.
4. `.txt` 매니페스트 합성 → Storage `book-manifests` 업로드 (`sync_book_dash_v2.py`가 쓰는 형식).
5. `books` 행 전환 — `content_type` `'html'` → `'asb_native'` + `content_url` = 매니페스트 URL.
   **스키마 변경 아님**(004 화이트리스트에 `asb_native` 이미 존재). 그래도 **ADR 선행 후 팀장 SQL**.
6. 비정형 12장(§4-2) 처리 방침 — 여백 패딩으로 폭을 맞출지 그대로 둘지.
7. 검증 — 전환 대상 권을 `/book/{id}/read`에서 실제로 열어 AsbReader 렌더 확인(팀장 육안).
8. 되돌리기 경로 확보 — 전환 전 `content_type`·`content_url` 원본 값을 CSV로 백업(1단계 SQL이 UPDATE이므로).

**주의 (Hard Rule 관련)**
- `attribution_text`·`license`는 건드리지 않는다. `content_type`·`content_url`만 UPDATE →
  `enforce_commercial_license` 트리거는 `NEW.license = OLD.license`라 통과.
- 5번은 DB 스키마 변경이 아니지만 **데이터 대량 UPDATE**이므로 ADR 선행 + 팀장 실행이 원칙.
