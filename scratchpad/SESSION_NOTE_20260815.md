## 5. ADR-0059 Open 항목 상태

| 항목 | 상태 |
|---|---|
| O-3 | 열림 — D1의 사용자 표시 문구 확정(팀장) |
| **O-4** | **사실상 해소** — 원인 확정 + 정리 COMMIT 완료. 문안은 아직 "조사 대기"다.<br>**다음 세션에서 종결 처리 여부를 판단**한다(문서 정합 작업 1건) |
| O-5 | 열림 — P1 화면 요구가 D2-b RPC 반환 형태를 정한다 |
| O-6 | 열림 — 다자녀 표시 규칙은 코드 실측으로 확정(`getActiveChild` = `created_at ASC LIMIT 1`),<br>테스트 계정 처분만 팀장 판단. R6 실행으로 `parent_id` 묶음·이름 표기(초은우/쵸은우) 확정 |
| O-7 | 신설 — 포인트 적립 경로 밖 증감(총 100P, 비차단) |

O-1·O-2는 이미 해소·삭제됐다(D2-b 확정 / 상한 실측 1,000).

**D1·D2 구현은 아직 착수 전이다.** D1은 `.range()` 청크 경로로 확정(상한 1,000이라
`.limit(N)` 판정 불가), D2는 RPC `get_mypage_summary` 확정. 실행 순서는 ADR 말미 참조.
단, 오늘 정리로 세션이 56행이 되어 **절단은 현재 발생하지 않는다** — D1·D2의 긴급도는
내려갔으나 취소는 아니다(다음 선별 작업·실사용자 증가 시 재발).

## 7. 불변 규율 (요약)

3자 구조(팀장 결정·DB 실행 / 오케스트레이터 설계·지시서 / 워커 파일·git·스크립트) 유지.
`git add`는 파일명 명시(`git add .` 금지) · add → commit → push **3단계 별도 승인** ·
커밋 메시지 단일 `-m`, 트레일러 0건 · push STEP 0으로 `gh auth status` → crspiegel 확인 ·
DB·Storage는 팀장 전속이며 워커가 만드는 SQL은 **ROLLBACK으로 끝내고 COMMIT은 팀장이 타이핑** ·
SQL은 보고문이 아니라 **파일에서 복사해** 전달 · SQL Editor에서 `CREATE TEMP TABLE` 금지(CTE 사용) ·
생성 SQL은 pglast 검증, 목록 대조 전 CRLF 제거 · 수량·상태 판정은 실측만 ·
예상 밖 상황은 즉시 STOP 후 보고.
